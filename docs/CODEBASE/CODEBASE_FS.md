# lnxrm 代码库组织与子系统说明（6：文件系统）

> 配套文件：`CODEBASE_OVERVIEW.md`（§1 总览）、`CODEBASE_BOOT.md`（§2 启动）、`CODEBASE_MEMORY.md`（§3 内存）、`CODEBASE_PROC.md`（§4 进程·调度·信号）、`CODEBASE_SYSCALL.md`（§5 系统调用与 ABI）、`CODEBASE_DRIVERS.md`（§7 驱动）、`CODEBASE_SMP.md`（§8 SMP 与 ACPI）、`CODEBASE_SELFTEST.md`（§9 自测）、`CODEBASE_INVARIANTS.md`（§10 关键不变式）。构建与运行见 `../BUILD/BUILD.md`，差距与计划见 `../GAP_ANALYSIS.md`，项目概览见 `../README.md`。本文为 §6 文件系统。

层次：`vfs.c`（vnode/file/fd 表/路径解析/挂载）→ `blk_cache.c`（64 项时间戳 LRU + `blk_io_*` **唯一驱动调用点**，C10 起还负责每设备请求队列；**S2 后只服务 FAT32**，ext2 块层直走 `blk_io_*`）→ `mbr.c` → `ext2/`（挂载/目录/文件/元数据，**S2 起挂根**，直写设备）与 `fat32/`（挂载/目录/文件/元数据/redo journal）。`pipe.c`、`shm.c` 与 `ipc/dipc.c` 都不在层次里——前者没有 vnode、直接挂在 fd 表上，后两者连路径都不走（名字在它们自己的表里），见下。

- **VFS 对象**：`vnode` 每次 open 在栈上创建拷贝（无持久 inode，两 fd 的 `pos` 独立，`ino/dev/ro` 供 `stat`）；`file` 走 kmalloc + CAS 引用计数（不回绕、不二次 free），**`priv` 与 `drv` 分开**——`priv` 是 `struct vnode *`（`vfs_file_size`/`vn_size_now`/`sys_mmap` 都解引用它），`drv` 是无 vnode flavour 的私有对象（`pipe` 端点存 `struct pipe *`），两者不会同时非 NULL；`fs_ops` 12 钩子（`size` 供 `O_APPEND`、`close_node` 由 fs 决定释放方式）。
- **pipe（47，`fs/pipe.c`）**：`struct pipe` = 自旋锁 + 4096 B 环 + `rd/wr/used` + `nreaders/nwriters`（计**文件描述**，dup2/fork 共享一份、refcnt 归零才轮到 close 递减）+ `rwait/wwait`；两端各一个 `file_ops`（读端只有 `read`、写端只有 `write`，缺门回 `EBADF`）。等待队列前插单链复用 `task->wait_next`（与 input_event 的 evq 同字段，同一时刻只 park 一处）：push/unlink/detach 持 pipe 锁、**wake 必须锁外**（`sched_wake_task` 取 `runq_lock`，全仓不嵌套），每方向**唤醒全部**；park 协议同 `input_event_wait`（锁内入队 + `T_SLEEPING` + 出队 → `schedule()` → 锁内 unlink + 恢复 `T_RUNNING` → 重查条件）。写入醒读者、读腾空间醒写者、末端 close 悟醒对侧（EOF/EPIPE），**先 wake 再 `kfree`**；整笔写放得下才一次锁内落盘（`sys_write` 已钳 4096 = `PIPE_SZ`）。
- **shm（51/52，`fs/shm.c` + `include/sys/shm.h`）**：32 桶名字哈希（`shm_lock` irqsave），每个 `struct shm_ent` 持**唯一的一个 `struct file`**——`shm_open` 对已存在的名字只 `refcnt++` 交出同一指针。这一条让三件事自动成立、**MM 层零改动**：`mm/filepage.c` 以 file 指针作键故两个 opener 必然同一帧、`sys_mmap` 的 `!priv`/`V_REG` 门开、`vma_fork_shared` 复制的还是同一个 file。伪 vnode 合成 `V_REG` 走 **`priv` 不走 `drv`**（C42 与 pipe 的标记不冲突）：`fs_ops.size` 创建时页对齐**定死**、`read` 补零、`write` **返回 n 却不存字节**（让 `vma_writeback` 清 `PG_D` 而不是无限重试）；`file_ops` 只有 `.close = reg_close`，`read/write/getdent = NULL` ⇒ `sys_read/write` 回 `EBADF`（所有 opener 共享一个游标）。**生命周期两条线一扇门**：entry 的引用**只有 `shm_unlink` 放**，故 `close_node` 必然在 unlink 之后并无条件 `kfree(ent)`（仍 named 则先摘表 + 警告），副带**内容跨 close 存活**（POSIX）；两个顺序坑与 `kmalloc` 二次查表见 §10。名字去前导 `/`、拒空与内部 `/`、`<32` 字节（`ENAMETOOLONG`）；mode 恒 `O_RDWR`（`O_RDONLY/WRONLY/RDWR` 接受并忽略），只认 `O_CREAT|O_EXCL`、其余位 `EINVAL`；1 GiB（`ENOMEM`）、64 对象（`ENOSPC`）、**无 gate**。51/52 不进 systest（`SYSTEST_TAGS` 173 条、smoke 总数不变），只落 `t_shm.c` 三例（全不阻塞）。
- **dipc（53–55，`ipc/dipc.c` + `include/sys/dipc.h`）**：结构抄 shm（唯一 `struct file` ⇒ 共享帧缓存、mmap 门、`vma_fork_shared` 自动成立、**MM 层零改动**），但**连路径都不走、不注册进 `shm_open` 命名空间**——`shm_open("ps2")` 恒 `ENOENT`，原始字节流只可能从 `dipc_open` 拿。**环**住通道自己的 file page：页首 `struct dipc_hdr{u32 rd,wr}`（8 B）+ 4088 B payload，容量 4087、满 = `ring_next(wr)==rd`（payload 非 2 的幂，`ring_next` 分支绕回而非掩码）；**索引写在帧里**，ring3 mmap 出来即无 syscall 读余量，越界由 `ring_check` 归零（见 §10）。`copy_*_user` 不补缺页 ⇒ 直接在 `dipc_lock` 内从帧拷到用户缓冲、**无需 kstack bounce**；wrap 拆两段拷、`rd` 只在两段都成功后推进（**`EFAULT` 不消耗数据**）。**等待链**复用 `task->wait_next`（与 pipe/input_event 同字段），push **锁内摘整条链、锁外**逐个 wake（先取 `next`）；recv 的 park 协议照抄 `pipe.c:186-197`（醒后 unlink + **恢复 `T_RUNNING`** 再重查）。**生命周期两条线一扇门**照搬 shm（见 §10）；失败回滚走 `pmm_free → filepage_drop_file → kfree(priv) → kfree(f) → kfree(d)` 而非 `vfs_close_file`。反向 send **不走环**：拷进内核 1 KiB 缓冲后**锁外**调 create 时装的 `sink`——**S1c 起 `kbd`/`mouse` 的 sink 承载 ring3 解码结果的回传**（`kbd_sink`/`mouse_sink`，见 §7）。三行全 `GATE_ADMIN`（8→11）；**第 4 参走 `r10`**（S3.2 起，与 `h_mmap` 同款，分发层零布线）。`dipc_push(name,…)` **按名字查表**（IRQ 安全），环满丢字节计 `dropped`。53–55 刻意不进 systest（173 条、smoke 总数不变），只落 `t_dipc.c` 四例（**全不阻塞**，park 半段用假任务直接驱动）。
- **路由**：`fs_for_path` 按**最长前缀 + 组件边界**选唯一挂载项（`"/"` 不吞 `/alt`），`ops` 与 `priv` 成对取自它；`vfs_umount` 只动路由**不 free priv**；跨挂载 `rename` 回 `EXDEV`；挂载入口只有 `vfs_mount_fs`/`vfs_umount`（**非 syscall**）。
- **cwd（49/50）**：`struct task.cwd[128]` 是所有路径解析的基准——`abs_path()` 把相对路径拼在它之后（slot claim 置 `"/"`、`fork` 复制、`execve` 保留），故 open/stat/unlink/mkdir/… 无需逐个改动；`chdir` 解析存在性后整段替换，`getcwd` 只读拷回。`abs_path` **不折叠 `.`/`..`**（点段原样交给 fs：ext2 的目录里有真 `.`/`..` 记录，根上 `ls .` 正常；FAT 卷仍无点记录故 FAT 根上 `ls .` 是 `ENOENT`，见 GAP 第 6 节）。
- **错误契约**：`blk_io_*` 驱动非 0 原样上抛 → `fat_*_sector` 只有 0 或 `LNXRM_EIO` → 目录扫描三态 `1/0/负` → 语义层负数一路上传不被改写（对外 `[fat32] I/O error` + `-5`；ext2 侧同款：坏块 `beyond the volume … refused` + `-5`，坏目录记录停在原地 + 对应负 errno）。
- **路径不变式（同一扇区只走一条路）**：数据/目录经块缓存，FAT 区 `m->fat_pages` 分帧直写/入日志，挂载期 `blk_io_*` 直读；FAT 表 4 KiB 分帧驻留，表项与扇区永不跨帧，访问只走 `fat_entry_get/put_raw/sector_ptr`（其余见 §10）。
- **块缓存**：64 项 × 512 B，键 `(dev,lba)`，时间戳 LRU；读失败作废 victim；**三道同步门**进 `blk_cache_sync_all()`——BSP 每秒 tick / 最后 fd close / `panic()` try 回写（外加 `SYS_sync(33)`），**写回失败保持脏**。**C7 起 `cache_lock` 只做元数据**：fill 先占槽、写回先拷任务自己的弹跳缓冲，victim/purge 跳 `busy` 槽，`blk_io_*` 全在锁外；tick 回写门改 trylock；写回失败进 `tried` 位图重试。
- **块请求队列（C10）**：`blk_io_read/write` 两段式——phase 1 持设备 `io_lock` 把请求（节点在调用者栈上）追入该设备 FIFO 后放锁；phase 2 重新持锁 `blk_drain_locked()` **排空整队按到达序执行**（含别的 CPU 中途入队的），排空到空即自身 `BLK_REQ_DONE`，读栈上 `status` 即返回值、无自旋。错误只记在该请求自己的 `status`；**驱动不再自带锁**（`ide_lock`/`ahci_lock` 已删），两盘经各自 `io_lock` 真并行，分区走「分区 → 父盘」嵌套序。合并/取消未做（调用者仍压着 `fat_fs_lock`，待 C7 余项）。
- **ext2（S2，`fs/ext2/` + `include/ext2.h`）**：`ext2.c`（挂载校验、路径切分、目录记录编辑、12 个 `fs_ops` 回调）+ `block/block.c`（块层：整块读写 / `ext2_bmap` / 组位图分配 / 截断）+ `inode/inode.c`（inode 表读写）。**node 只存 `{ino, is_dir}`**——长度、权限每次操作都从盘上重读（两个 fd 对长度一致，沿用 `fat_size_impl` 的同一条规则）；**块层直走 `blk_io_read/write`，不过 `blk_cache_*`**（写回缓存只留给 FAT32；ext2 每次写入在回调返回前已落盘，`block.c` 头注释写明了为什么）；**一个 4 KiB 块 = 一次整块请求**（8 扇区单次 `blk_io_*`，读写皆然）——`ahciBlkWrite` 每次写请求收尾发一次 `0xE7` FLUSH，逐扇区写会把 enospc 填盘放大成约 50 万次 flush、烧穿 smoke 的 420 s 等待门（2026-11-24 修，账在 `ext2_read_data_block` 的注释里；`make smoke` 实测 **270/270**）。**一把 `ext2_fs_lock`**（`EXT2_ENTER/LEAVE`）包住全部回调；**六个变更回调（`write`/`create`/`mkdir`/`unlink`/`rmdir`/`rename`）以 `ext2_finish()` 收尾**：`space_dirty` 则同步空闲计数，**失败路径也走**——直写已落盘，无需 flush；FAT journal commit 的同款门（e2fsck 的口供要求任何成功回调都不留下待写尾巴）。**`write()` 的 `n == 0`（O_TRUNC）分支也必须走这扇门**：`ext2_truncate_blocks()` 已把计数改回并置 `space_dirty`，不收尾就不写回，于是 `O_TRUNC` 看到的仍是「满盘」——2026-11-23 `test_enospc`（填满根卷）之后 `test_mmap_file` 的 `open(/FMAP.T, O_CREAT|O_TRUNC)` 因此拿到 ENOSPC（`t_mmap.c:762`）。**目录记录逐字节照抄 Linux `ext2/dir.c`**：`rec_len` 认领时切分、删除时并回前一条，块内链恒落在最后字节——**`e2fsck -n` 是唯一裁判**（Makefile 造完镜像即查，smoke 每轮 carry-over 再查）。**地址映射** 12 直接 + 一级 + 二级；分配只碰 `bg_free_blocks_count` 还非 0 的组，**位图位与描述符/超级块三处计数在同一次改**（e2fsck 拿三处对账）。**`getdent` 返 `1/0/负`、cookie = 目录字节偏移**（恢复点就是 `off`，洞整块跳过）；**目录 vnode 的 `size` 恒 0**（`O_APPEND` 不会往目录里追加）。**`write(NULL, 0)` = `O_TRUNC`**（vfs 的截断路径靠它）；**`vnode.ro = (i_mode & 0222) == 0` 按各自 inode 的 mode 定**——0444 文件真的只读，这是 FAT `ATTR_READONLY` 表达不了的。**语义钉**：`unlink` 对目录 `-1`、`rmdir` 非空 `-39` / 对文件 `-20`、类型不匹配双向 `ENOTDIR`；mutation 末组件是 `.`/`..` 一律 `EINVAL`（六个入口各挡一次，`ext2_split_is_dot`）。**`rename` 照抄 Linux `ext2_rename`**：同父改名只动记录、跨父连 `..` 一起搬、`ext2_is_ancestor` 防目录自环；跨挂载 `EXDEV` 由 `vfs_rename_path()` 在进 fs **之前**拦。**路径契约**：fs 收到的路径**无前导斜杠**、root 传 `""`（`split_path("")` 返 `EINVAL`，根自身由 `ext2_lookup("")` 直答）。**坏数据必出声**：每一处目录扫描撞上非法 `rec_len` 都打一行并停在原地（`lookup/scan/add/delete/set refused`、`".." not moved`），越界块打 `beyond the volume … refused`。
- **FAT32**：挂载校验 BPB（55AA、`"FAT32"`、簇因子 2 的幂、`bps==512`），九处拒绝统一 `fat_reject()`；目录可用槽 = 尾槽 0x00 与已删 0xE5，**0x05 是活记录**，槽不够先扩链 ⇒ 目录永不满而 ENOSPC；getdent cookie = `(簇<<32)|字节偏移` 物理恢复点；LFN 校验 checksum + 序号递减，坏即回落 8.3；簇链 `FAT_CHAIN_MAX_STEPS` 步数预算 + 单簇自环即断。**S2 起不再当根**：`find_volume()` 先整盘 ext2、再整盘 FAT、最后逐分区（分区内同样 ext2 先试），FAT 仍可挂 `/mnt`。
- **redo journal**：reserved 空闲扇区，扇区 8 superblock（magic `JRN1`，`head` 是相对偏移）；locked wrapper `begin → *_impl → commit`，**失败路径也 commit**；顺序 ①flush 数据 ②写记录 ③superblock 置 **COMMIT（唯一提交点）** ④apply ⑤flush ⑥CLEAN，**④ 失败必须保留 COMMIT**；mount 时 `state==COMMIT` 幂等 redo。
- **挂载顺序**：`vfs_try_mount_disk` 逐盘**先整盘 ext2、再整盘 FAT32、最后 MBR 分区**（每分区先 `blk_register` 再试，分区内同样 ext2 先试——两探针互认不出对方的卷：ext2 只认 `0xEF53` magic，FAT 的 BPB 检查在 ext2 镜像的空 boot block 上过不了）→ 分流（有 `/bin/init` 挂 `/`，余挂 `/mnt`），挂载行按 kind 打 `[vfs] ext2 mounted at / (whole disk, has /bin/init)`。`blk_register` 满 8 槽**大声拒绝且表不变**。**没有第二条路**：initramfs（`initramfs.c`/`mkinitramfs.py`/`.initramfs` 段/`vfs_mount_initramfs()` 回退）整套删除——它曾让「根挂不上」悄悄降级成只读 cpio 根，掩盖真故障；现在挂不上就是挂不上。
- **`/mod`（S1b）**：`disk.img` 多一个 `/mod` 目录（`debugfs` 脚本建，S2 起；文件名与 `build/mod/` 里**完全一致**——`.km` 由 `MOD_ELFS` 在**链接期**加上，安装步骤只做 `basename` 搬运），装 ring3 驱动模块。`init` 在 README 打印之后、`fork` 终端之前 `kopen("/mod") → kgetdent` 扫一遍，校验 `.km` 三字符后缀（**大小写不敏感**：这条判据从 FAT 时代原样保留——镜像里的名字恒为小写，ext2 的大小写敏感路径解析会让 `X.KM` 在 exec 阶段大声失败而非静默）后 `kfork + kexecve`，**每个模块一个子进程**、init 本身继续当 reaper；**成功路径一行不打印**（2026-11-18：`init: module ...` 与统计行都拿掉了，驱动正常加载本就该是隐形的），**失败才出声**——`/mod` 打不开、`kgetdent` 出错、名字过长、`kfork`/`kexecve` 失败各一行，另外扫描后**一个模块都没起来**才打统计行 `init: N file(s) in /mod, 0 spawned -- no module was started`（健康 boot 静默），**pid 1 仍永不因此退出**。发现靠目录扫描而非链期名单——加一个驱动 = 往镜像里放一个文件。
